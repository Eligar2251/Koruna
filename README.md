# ЦСБ — Центральная Строительная База

Сайт на Next.js и React с сохранённым оформлением Tilda. У каждой страницы свой файл стилей рядом с React-кодом. Каталог, корзина, заказы и админка работают через серверные API приложения.

## Запуск

Требуется Node.js 20 или новее.

```bash
npm ci
cp .env.example .env
# Заполните SUPABASE_URL и SUPABASE_ANON_KEY в .env.
npm run build
npm start
```

Админка: `/admin`. Каталог: `/katalog`. Корзина: `/korzina`.

После получения изменений нужна новая сборка, а не только перезапуск старой:

```bash
git pull origin arena/edb2e7e6-koruna
npm ci
npm run build
# Затем перезапустите запущенный процесс приложения командой вашего хостинга.
# Если запускаете вручную: остановите старый npm start и выполните npm start снова.
```

Десктопные блоки используют безразмерный коэффициент `--csb-scale`. Выражения `scale(calc(100vw / 1200))` и `height: calc(550px * 100vw / 1200)` некорректны: браузер отбрасывает их и блоки могут схлопнуться. Исправление есть в стилях всех страниц и в конвертере `scripts/port-react.py`.

## Подключение Supabase

Для работы сайта нужны **только две переменные**:

```dotenv
SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
SUPABASE_ANON_KEY=your-anon-key
```

`DATABASE_URL` и пароль Postgres приложению не нужны. `SUPABASE_SERVICE_ROLE_KEY` для каталога, загрузки фото, заказов, входа и назначения администраторов тоже не нужен. Нельзя подменять им anon key.

Клиент Supabase создаётся на сервере с anon / publishable key. После входа используется JWT пользователя Supabase Auth; доступ к изменениям разрешают RLS-политики и запись пользователя в `admin_users`. Ключи из окружения не передаются в клиентский JavaScript; не добавляйте их в `NEXT_PUBLIC_*`.

Если Supabase вообще не настроен, доступен локальный режим предпросмотра: данные в `data/`, фото в `uploads/`. Эти каталоги не попадают в git. Это не подключение к вашей базе Supabase.

### Подготовка базы и первого администратора

Миграции в `supabase/migrations/` выполняются по порядку через **Supabase SQL Editor** — строка подключения базе для этого не нужна:

1. `20261017120000_clean_database.sql` — необратимая очистка `public`. **Только для первоначальной очистки, не повторять на заполненной базе.** Файлы Storage и пользователей Authentication не удаляет.
2. `20261017120100_catalog.sql` — категории, товары, `admin_users`, бакет фото.
3. `20261017130000_harden_catalog.sql` — права доступа и RLS.
4. `20261017140000_orders_staff.sql` — заказы и назначение администраторов.
5. `20261017140100_seed_catalog.sql` — базовые категории и товары.

Если база уже развёрнута, выполняйте только ещё не применённые миграции. Не запускайте очистку ради обновления сайта.

Первого пользователя создайте в Supabase → Authentication → Users (с подтверждённой почтой), затем назначьте его администратором в SQL Editor:

```sql
insert into public.admin_users (user_id)
select id from auth.users where email = 'admin@example.ru'
on conflict do nothing;
```

После этого входите на `/admin` с его почтой и паролем. Новых администраторов назначает существующий администратор из панели. Создание пользователей использует Supabase Auth sign-up: проект должен разрешать регистрацию; если включено подтверждение почты, новому пользователю нужно его пройти. Пароли обрабатывает Supabase Auth, а не service role.

Фото в Supabase загружаются в бакет `product-images` под JWT администратора. Анонимный ключ не даёт права изменять каталог, читать заказы или список администраторов.

### Сохранённые инструменты очистки

Существующие скрипты очистки сохранены. Они не запускаются при старте приложения, сборке или миграции автоматически.

- Для очистки SQL-схемы без строки подключения используйте `supabase/clean.sql` в SQL Editor. Это разрушительная операция, не обычное обновление.
- Для удаления файлов Storage через API нужен отдельный серверный `SUPABASE_SERVICE_ROLE_KEY`. Только для этой ручной операции можно временно задать его в окружении и вызвать `npm run clean -- --storage-only --dry-run`; удаление требует отдельного подтверждения `--yes`. Не удаляйте строки `storage.objects` напрямую: файлы останутся в S3.
- Старый режим очистки через прямое соединение Postgres остаётся в утилите для совместимости. Он не является настройкой сайта и не нужен при работе через SQL Editor. Не добавляйте его реквизиты в окружение приложения.

Не публикуйте реальные ключи, пароли и `.env`.
